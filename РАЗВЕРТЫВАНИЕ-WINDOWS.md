# Развёртывание НормАрхива на рабочем ПК с нуля

Инструкция предназначена для чистого Windows-компьютера и локальной демонстрации приложения. Сервер и база данных размещаются на рабочем ПК; зрители открывают сайт в браузере. Для постоянной эксплуатации организации потребуется отдельная production-настройка со службой Windows, HTTPS, резервным копированием и согласованием с ИТ.

## 1. Что понадобится

- Windows 10/11 с правами на установку программ. Для установки правила брандмауэра нужны права администратора.
- Node.js версии 22.12 или новее (LTS рекомендуется).
- PostgreSQL версии 15 или новее и pgAdmin 4 либо `psql`.
- Папка проекта `shaky-shell`, перенесённая на рабочий ПК.
- Для доступа с других компьютеров — подключение к одной локальной сети.

В проекте уже есть `package-lock.json`; зависимости устанавливаются командой `npm ci`.

## 2. Установить и проверить Node.js

1. Скачайте установщик LTS для Windows с официального сайта Node.js и установите его с настройками по умолчанию.
2. Закройте и заново откройте PowerShell, чтобы обновился `PATH`.
3. Проверьте установку:

```powershell
node --version
npm --version
```

`node --version` должен вывести `v22.12.0` или выше.

## 3. Установить PostgreSQL и создать пустую базу

1. Установите PostgreSQL 15+ для Windows. Запомните пароль пользователя `postgres`, заданный установщиком, и оставьте порт `5432`, если он свободен.
2. Убедитесь, что служба PostgreSQL запущена: откройте `services.msc`, найдите службу PostgreSQL и проверьте состояние «Работает». Либо откройте pgAdmin и подключитесь к локальному серверу.
3. В pgAdmin создайте отдельную роль приложения:
   - **Login/Group Roles → Create → Login/Group Role**;
   - задайте имя, например `normarchive_app`;
   - во вкладке **Definition** задайте надёжный пароль;
   - во вкладке **Privileges** включите **Can login?**;
   - сохраните роль.
4. Создайте базу `normarchive`:
   - **Databases → Create → Database**;
   - имя: `normarchive`;
   - владелец: `normarchive_app`;
   - сохраните.

Если в pgAdmin нет возможности назначить владельца при создании, создайте базу от имени администратора PostgreSQL, затем откройте Query Tool на базе `postgres` и выполните, подставив созданное имя роли:

```sql
ALTER DATABASE normarchive OWNER TO normarchive_app;
```

Не открывайте порт PostgreSQL в брандмауэре для всей сети: для этой схемы к базе подключается сервер приложения на том же компьютере.

## 4. Перенести проект и установить зависимости

Скопируйте папку `shaky-shell` на рабочий ПК, например в `C:\Apps\shaky-shell`. Не копируйте с исходного компьютера папки `node_modules` и `dist`: они не нужны, зависимости будут установлены заново, а сборка создана на целевом компьютере.

Откройте PowerShell и перейдите в папку проекта (путь замените на фактический):

```powershell
Set-Location 'C:\Apps\shaky-shell'
npm ci
```

Дождитесь успешного завершения команды. Не закрывайте PowerShell, если появится сообщение об ошибке: оно поможет найти причину.

## 5. Настроить `.env`

Создайте файл `.env` в корне проекта на основе `.env.example`. Например, в PowerShell:

```powershell
Copy-Item .env.example .env
notepad .env
```

Заполните параметры:

```dotenv
DATABASE_URL=postgresql://normarchive_app:ВАШ_ПАРОЛЬ@127.0.0.1:5432/normarchive
DB_POOL_SIZE=20
ARCHIVE_STORAGE_DIR=C:/ProgramData/NormArchive/files
PUBLIC_BASE_URL=http://localhost:4321
APP_ALLOWED_HOSTS=localhost,127.0.0.1,192.168.1.20
```

- В `DATABASE_URL` укажите настоящий пароль роли PostgreSQL, имя базы и порт. Если пароль содержит символы вроде `@`, `:`, `/`, `#` или `%`, их нужно URL-кодировать. Для демонстрации проще задать роли пароль из букв и цифр с подходящей длиной.
- `ARCHIVE_STORAGE_DIR` — папка, в которой приложение хранит загруженные файлы. Приложение может создать её, но учётная запись Windows, под которой запущен Node.js, должна иметь права на запись.
- `PUBLIC_BASE_URL` оставьте таким для локальной демонстрации. Это не адрес для входа зрителей; браузеры в сети будут открывать IP компьютера и порт. Открытие DOCX/XLSX во внешнем Office с другого ПК может требовать отдельно доступный адрес и HTTPS.
- В `APP_ALLOWED_HOSTS` перечислите через запятую `localhost`, `127.0.0.1` и фактический IP/имя сервера, по которому к сайту обращаются браузеры. Это только имена хостов: без схемы `http(s)://`, пути и порта. После изменения `.env` выполните production-сборку заново.

Сохраните файл в UTF-8. Не пересылайте `.env`, не выкладывайте его в репозиторий и не публикуйте пароль базы. Файл `.env` исключён из Git.

## 6. Применить схему базы данных

Убедитесь, что PostgreSQL запущен, затем из корня проекта выполните:

```powershell
npm run db:migrate
```

Команда применит SQL-миграции и создаст таблицы приложения. При успешном выполнении в выводе будут строки `Applied: ...` для миграций. Повторный запуск безопасен: уже применённые версии будут пропущены.

## 7. Создать первого администратора

В том же окне PowerShell задайте учётные данные. Замените примерные значения собственными; пароль должен быть не короче 12 символов:

```powershell
$env:BOOTSTRAP_ADMIN_USERNAME = 'admin'
$env:BOOTSTRAP_ADMIN_PASSWORD = 'ЗаменитеНаСвойДлинныйПароль'
$env:BOOTSTRAP_ADMIN_NAME = 'Администратор'
npm run admin:create
```

После сообщения об успешном создании можно очистить переменные текущего сеанса:

```powershell
Remove-Item Env:BOOTSTRAP_ADMIN_USERNAME, Env:BOOTSTRAP_ADMIN_PASSWORD, Env:BOOTSTRAP_ADMIN_NAME
```

Первый администратор создаётся только в пустой базе. Не добавляйте эти переменные в `.env` и не сохраняйте пароль в скрипте. При первом входе смените пароль через меню профиля.

## 8. Собрать и запустить production-версию

Для постоянной работы не запускайте `npm run dev`: сначала создайте production-сборку из корня проекта:

```powershell
npm ci
npm run build
```

В `.env` в корне проекта добавьте или измените строки:

```dotenv
HOST=0.0.0.0
PORT=4321
```

Оставьте `DATABASE_URL` и `ARCHIVE_STORAGE_DIR` настроенными, а `TOTP_ENCRYPTION_KEY` задайте случайным 32-байтовым ключом в hex (64 символа). В production ссылку `PUBLIC_BASE_URL=http://localhost:4321` не используйте для Office: создание ссылок редактирования требует HTTPS. Для обычной работы каталога в локальной сети эту настройку можно удалить.

Перед запуском настройте правило брандмауэра из шага 9. Затем запустите production-сервер из корня проекта:

```powershell
node --env-file-if-exists=.env .\dist\server\entry.mjs
```

Проверьте сайт на `http://localhost:4321`. Это production-сборка, не сервер разработки; пока PowerShell открыт, сервер работает. Для доступа после перезагрузки настройте автозапуск в шаге 11.

## 9. Разрешить доступ только из локальной сети

Убедитесь, что подключение именно к доверенной домашней/офисной сети и его профиль Windows — **Частная сеть**. Не переключайте профиль в «Частная сеть» для общедоступного Wi-Fi. Чтобы узнать локальную подсеть сервера, откройте PowerShell и выполните `ipconfig`; например, IP `192.168.0.138` с маской `255.255.255.0` обычно находится в подсети `192.168.0.0/24`. Желательно закрепить IP-адрес за компьютером в настройках роутера.

Откройте PowerShell **от имени администратора** и разрешите входящие подключения на порт приложения только из локальной подсети:

```powershell
New-NetFirewallRule -DisplayName 'НормАрхив production LAN 4321' -Direction Inbound -Protocol TCP -LocalPort 4321 -RemoteAddress LocalSubnet -Action Allow -Profile Private
```

Не создавайте правило для профиля Public, не отключайте брандмауэр и не настраивайте на роутере переадресацию порта 4321. Если правило запрещено корпоративной политикой, обратитесь к ИТ-администратору.

Чтобы узнать адрес компьютера, выполните `ipconfig` и найдите IPv4 активного Ethernet/Wi-Fi адаптера. На другом устройстве той же сети откройте `http://АДРЕС_КОМПЬЮТЕРА:4321`, например `http://192.168.0.138:4321`. Не используйте адреса VPN или виртуальных адаптеров. Некоторые гостевые Wi-Fi сети запрещают устройствам связываться друг с другом.

## 10. Проверить приложение

1. Войдите под созданным администратором на `http://localhost:4321` или сетевом адресе.
2. Добавьте тестовый документ и небольшой PDF/DOCX/XLSX, проверьте каталог и открытие карточки.
3. Проверьте административные разделы и импорт только на тестовых данных.
4. Убедитесь, что новый файл появился внутри `ARCHIVE_STORAGE_DIR`.
5. Перед показом удалите тестовые записи, если они не нужны.

Пустой архив после начальной настройки — ожидаемое поведение: в новой базе нет документов, пока вы не добавите или не импортируете их. Прямое подключение по HTTP не шифрует пароли и файлы; используйте его только в доверенной локальной сети. Для конфиденциальных данных настройте HTTPS с внутренним сертификатом через ИТ-службу.

## 11. Настроить автозапуск production-сервера

Чтобы приложение запускалось после перезагрузки Windows без открытого окна PowerShell, настройте встроенный **Планировщик заданий**:

1. Откройте меню «Пуск», найдите и запустите **Планировщик заданий** (`taskschd.msc`), затем выберите **Создать задачу**.
2. На вкладке **Общие** задайте имя `НормАрхив production`. Укажите ту же учётную запись Windows, которой разрешено читать папку проекта и `.env`, записывать файлы в `ARCHIVE_STORAGE_DIR` и подключаться к PostgreSQL. Выберите запуск независимо от входа пользователя в Windows.
3. На вкладке **Триггеры** добавьте триггер **При запуске**.
4. На вкладке **Действия** выберите **Запуск программы**. В поле **Программа или сценарий** укажите путь к Node.js; его можно узнать командой `(Get-Command node).Source` в PowerShell. В **Добавить аргументы** укажите, заменив путь на фактический:

   ```text
   --env-file-if-exists="C:\Apps\shaky-shell\.env" "C:\Apps\shaky-shell\dist\server\entry.mjs"
   ```

   В поле **Рабочая папка** укажите каталог проекта, например `C:\Apps\shaky-shell`.
5. На вкладке **Параметры** включите перезапуск задачи при сбое. Сохраните задачу; Windows может запросить пароль выбранной учётной записи.
6. Щёлкните задачу правой кнопкой мыши и выберите **Выполнить**. Проверьте `http://localhost:4321` и страницу с другого устройства локальной сети.

Если проект расположен не в `C:\Apps\shaky-shell`, замените путь и в команде запуска, и в поле рабочей папки. Остановить приложение можно через **Завершить** в Планировщике заданий; повторный запуск — через **Выполнить**. PostgreSQL-служба тоже должна запускаться автоматически. После изменения кода повторите `npm ci` (если изменились зависимости), `npm run build`, затем перезапустите задачу.

## 12. Передача существующих данных

Эта инструкция создаёт чистый архив. Чтобы перенести уже созданные документы, необходимо перенести и восстановить **оба** компонента:

1. резервную копию PostgreSQL-базы;
2. содержимое каталога `ARCHIVE_STORAGE_DIR` с сохранением структуры файлов.

Затем обновите `DATABASE_URL` и `ARCHIVE_STORAGE_DIR` в `.env` на целевом ПК. Один перенос исходного кода не переносит пользователей, документы или файлы. Перед переносом сделайте резервные копии и проверьте восстановление; не заменяйте существующую базу без согласования.

## 13. Production-режим и разработка

`npm run dev` — только для разработки. Для постоянного LAN-запуска используйте `npm run build`, затем запускайте `node --env-file-if-exists=.env .\dist\server\entry.mjs` вручную или через Планировщик заданий. `npm run preview` предназначен для локальной проверки production-сборки, а не для постоянной работы. Не публикуйте сервер в интернет и не используйте незашифрованный HTTP в недоверенной сети.
