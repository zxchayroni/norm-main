# Возможные проблемы при запуске НормАрхива

Инструкция относится к развёртыванию на Windows по руководству [РАЗВЕРТЫВАНИЕ-WINDOWS.md](./РАЗВЕРТЫВАНИЕ-WINDOWS.md). Сначала проверьте, что команды выполняются из корня проекта — там находятся `package.json` и `.env`.

## «Отказано в подключении» или сайт не открывается

**На рабочем ПК:**

1. Проверьте, что окно PowerShell с сервером всё ещё открыто и в нём нет ошибки.
2. Убедитесь, что сервер запущен с привязкой ко всем интерфейсам:

   ```powershell
   npm run dev -- --host 0.0.0.0 --port 4321
   ```

   В выводе Astro ожидаются сетевые адреса. Если запустить только `npm run dev`, сервер может быть доступен лишь локально.
3. На самом рабочем ПК проверьте `http://localhost:4321`.
4. Посмотрите, слушает ли процесс порт:

   ```powershell
   Get-NetTCPConnection -LocalPort 4321 -State Listen
   ```

   Адрес `0.0.0.0` означает, что сервер слушает сетевые интерфейсы. `127.0.0.1` означает только локальный доступ.

**На втором ПК:**

1. На рабочем ПК выполните `ipconfig` и возьмите IPv4 активного сетевого адаптера, например `192.168.0.138`.
2. На втором ПК откройте `http://<IPv4-рабочего-ПК>:4321`, не `localhost`: `localhost` всегда указывает на сам компьютер, где открыт браузер.
3. Проверьте, что оба компьютера в одной разрешённой сети. VPN, гостевой Wi-Fi или изоляция клиентов могут блокировать связь.
4. Убедитесь, что правило брандмауэра разрешает TCP 4321 для профиля Private. Корпоративная политика может запрещать изменение правила — в таком случае обратитесь к ИТ.

Точечное правило, выполняемое от имени администратора:

```powershell
New-NetFirewallRule -DisplayName 'НормАрхив демо 4321' -Direction Inbound -Protocol TCP -LocalPort 4321 -Action Allow -Profile Private
```

Не отключайте весь брандмауэр. Если порт 4321 занят, выберите другой, например 4322, и используйте его и в команде запуска, и в адресе браузера.

## Astro сообщает, что другой dev-сервер уже запущен

В проекте уже работает другой экземпляр Astro. Не запускайте второй процесс на том же порту.

- Перейдите к первому окну терминала и остановите сервер сочетанием `Ctrl+C`, затем запустите нужную команду.
- Либо используйте отдельный порт и согласованный адрес:

  ```powershell
  npm run dev -- --host 0.0.0.0 --port 4322
  ```

  Открывайте `http://localhost:4322` или `http://<IPv4-рабочего-ПК>:4322`.

Проверить, кто слушает порт:

```powershell
Get-NetTCPConnection -LocalPort 4321 -State Listen
```

Не завершайте незнакомый процесс до проверки его назначения.

## Команда `node` или `npm` не найдена

- Установите Node.js 22.12+.
- Закройте PowerShell/VS Code и откройте снова, чтобы перечитать PATH.
- Проверьте:

  ```powershell
  node --version
  npm --version
  ```

- Если команд нет, проверьте, что установщик Node.js добавил Node.js в PATH, или повторно запустите установщик с этим параметром.

## `npm ci` завершается ошибкой

- Убедитесь, что PowerShell находится в папке с `package.json` и `package-lock.json`:

  ```powershell
  Get-Location
  Test-Path package.json
  Test-Path package-lock.json
  ```

- Проверьте доступ к интернету и повторите `npm ci`.
- Не удаляйте `package-lock.json` и не заменяйте `npm ci` случайной установкой глобальных пакетов.
- Ошибки компиляции нативных модулей Argon2 на Windows обычно означают неподходящую версию/архитектуру Node.js или неполную установку зависимостей. Используйте официальный 64-битный Node.js LTS 22.12+ и повторите установку.
- Если сеть организации блокирует npm registry, попросите ИТ разрешить нужный источник пакетов или подготовить установку по политике организации.

## Ошибка `DATABASE_URL is required`

Приложение не увидело параметр базы.

1. Проверьте, что `.env` находится рядом с `package.json`, а не называется `.env.txt`.
2. Убедитесь, что команда запущена из корня проекта и запускается через npm-скрипт (`npm run dev`, `npm run db:migrate`), который загружает `.env`.
3. Проверьте, что в `.env` есть строка `DATABASE_URL=...` без лишних кавычек и пробелов до имени параметра.
4. Не вставляйте пароль в чат или скриншот терминала.

## Не удаётся подключиться к PostgreSQL

Сообщения могут содержать `ECONNREFUSED`, `Connection refused`, `password authentication failed`, `database ... does not exist` или `role ... does not exist`.

1. Проверьте в `services.msc`, что служба PostgreSQL запущена.
2. Проверьте имя базы, имя роли, пароль и порт (обычно `5432`) в `DATABASE_URL`.
3. Проверьте в pgAdmin, что база существует, а роль может подключаться и является владельцем базы/имеет необходимые права.
4. Если меняли порт во время установки, используйте фактический порт в `.env`.
5. Если пароль содержит специальные символы URL (`@`, `:`, `/`, `#`, `%`), замените их на percent-encoded значения или временно назначьте роли безопасный для URL пароль из букв и цифр.
6. Для диагностики без показа пароля попробуйте подключиться к этой базе через pgAdmin теми же учётными данными.

Не открывайте порт PostgreSQL для всех компьютеров, если база и приложение работают на одном ПК.

## Форма входа сообщает «Сервис входа временно недоступен»

Такое сообщение появляется, если `POST /api/auth/login` вернул не JSON — например, из-за ошибки приложения или недоступности PostgreSQL. Проверьте журнал production-процесса за время попытки входа и:

1. Убедитесь, что служба PostgreSQL запущена и приложение подключается к той же базе, где создан пользователь.
2. Проверьте наличие `DATABASE_URL` в окружении production-службы; не публикуйте его значение.
3. Посмотрите HTTP-статус `POST /api/auth/login` во вкладке Network браузера. `502`/`503` обычно указывают на прокси или недоступную зависимость; `500` — на ошибку приложения, подробности которой должны быть в серверном журнале.

При временной недоступности базы форма входа остаётся доступна, а cookie выхода удаляется из браузера. Отзыв серверной сессии и новый вход всё равно требуют работающей базы.

## Вход отвечает `403` («Недопустимый источник запроса»)

Если во вкладке Response указано `Cross-site POST form submissions are forbidden`, это встроенная проверка Astro. Добавьте IP-адрес или имя сайта в `APP_ALLOWED_HOSTS` в `.env` (Windows) или `/etc/normarchive/normarchive.env` (Linux), без схемы и порта, затем пересоберите приложение с этим окружением и перезапустите службу. Например: `APP_ALLOWED_HOSTS=localhost,127.0.0.1,192.168.168.223`.

Если используется reverse proxy, он также должен передавать `Host` исходного сайта и устанавливать `X-Forwarded-Proto` (`$scheme` в Nginx). Не отключайте проверку источника запросов как обходное решение.

## Миграция не выполняется

- Убедитесь, что `npm ci` закончилось успешно, `.env` настроен, PostgreSQL запущен.
- Проверьте, что роль имеет права на создание объектов в базе и является владельцем базы, как описано в руководстве по развёртыванию.
- Запускайте `npm run db:migrate` из папки проекта; скрипт автоматически применяет файлы `db/migrations`.
- Если миграция сообщает, что объект уже существует, но миграция отмечена неприменённой, не удаляйте таблицы вручную: сначала проверьте, не использовалась ли эта база раньше, и сделайте резервную копию.
- Исправьте указанную причину в настройках базы и повторите команду. Уже успешно применённые миграции повторно не выполняются.

## Ошибка при создании администратора

- `BOOTSTRAP_ADMIN_*` обязательны. Задайте их в том же окне PowerShell перед `npm run admin:create`.
- Имя пользователя: 3–100 символов, латинские буквы, цифры, точка, дефис или подчёркивание.
- Пароль: от 12 символов.
- Имя администратора не должно быть пустым.
- Администратор создаётся только если в базе ещё нет администратора. Если он уже есть, войдите под ним; для сброса пароля используйте предусмотренную команду `npm run admin:password`, не удаляйте пользователя напрямую.
- Убедитесь, что переменные заданы в том PowerShell-сеансе, из которого запускается npm:

  ```powershell
  $env:BOOTSTRAP_ADMIN_USERNAME = 'admin'
  $env:BOOTSTRAP_ADMIN_PASSWORD = 'свой-длинный-пароль'
  $env:BOOTSTRAP_ADMIN_NAME = 'Администратор'
  npm run admin:create
  ```

Не добавляйте эти секреты в `.env`, скрипты или историю, предназначенную для совместного использования.

## Вход не принимает логин или пароль

- Проверьте, что база мигрирована и администратора создали именно в этой базе (значение `DATABASE_URL` должно совпадать).
- Логин администратора при создании нормализуется в нижний регистр; введите его без лишних пробелов.
- Если пароль сменили, используйте новый пароль. Учитывайте раскладку клавиатуры.
- После серии неверных попыток вход может временно блокироваться; подождите окончания блокировки и проверьте учётные данные.
- При необходимости смените пароль существующего администратора штатной командой `npm run admin:password`, следуя README.

## В приложении нет документов

В новой базе это нормально: схема не загружает демонстрационные документы. Создайте тестовый документ через интерфейс или импортируйте таблицу/архив через раздел «Импорт». Для показа используйте только тестовые данные.

Если данные ожидались, проверьте, что используется правильная база. Перенос проекта не переносит PostgreSQL и папку `ARCHIVE_STORAGE_DIR`.

## Не загружаются или не открываются файлы

- Проверьте, что `ARCHIVE_STORAGE_DIR` указывает на папку с доступом на запись для учётной записи Windows, запустившей Node.js.
- Убедитесь, что на диске есть свободное место и файл соответствует поддерживаемому формату/лимиту размера.
- Не размещайте каталог хранения внутри `public` или другой публично отдаваемой папки сайта.
- Посмотрите ошибку в терминале сервера; не считайте сообщение браузера достаточной диагностикой.
- Если файлы были перенесены отдельно, проверьте, что каталог и содержимое скопированы полностью.

## DOCX/XLSX не открывается в Office на другом ПК

Открытие файла из другого компьютера требует, чтобы адрес, сформированный приложением, был достижим с того компьютера. Ссылка на `localhost` указывает на компьютер пользователя, а не на сервер.

- Для демонстрации DOCX/XLSX откройте обычную карточку/скачивание из браузера либо вручную проверьте, что сетевой адрес доступен с клиента.
- Текущая функция выдаёт ограниченную по времени ссылку для просмотра через URI Office; она не сохраняет изменения Office обратно в архив.
- Для штатной production-интеграции Office потребуется согласованный HTTPS-адрес и отдельная интеграция редактирования/сохранения. Не пытайтесь решать это отключением защиты Office.

## Тестовый сайт не предназначен для реальной эксплуатации

`npm run dev` — режим разработки/демонстрации, не Windows-служба и не production-сервер. Если сайт нужен постоянно или будет содержать реальные документы:

- согласуйте развертывание с ИТ-службой;
- используйте управляемый запуск Node.js, ограниченные права службы и HTTPS reverse proxy;
- настройте резервное копирование и регулярно проверяйте восстановление базы **и** файлов;
- не публикуйте порт 4321 в интернет;
- согласуйте антивирусную проверку файлов и сроки хранения.

В проекте пока нет автоматического установщика Windows-службы и готовой настройки backup/restore. См. ограничения в [README.md](./README.md).
