# НормАрхив

Веб-архив нормативных документов организации. Приложение построено на Astro SSR с Node.js, PostgreSQL и локальной аутентификацией.

Светлая и тёмная темы переключаются кнопкой в верхней панели; выбор сохраняется в браузере и применяется на экранах входа, каталога и администрирования.

## Установка и развёртывание

Выберите инструкцию для операционной системы сервера:

- [Ubuntu Server 24.04 LTS](./РАЗВЕРТЫВАНИЕ-LINUX.md) — установка версии проекта с GitHub для работы в локальной сети без домена.
- [Windows 10/11](./РАЗВЕРТЫВАНИЕ-WINDOWS.md) — production-сборка, автозапуск и доступ только из локальной сети.

## Требования

- Node.js 22.12 или новее;
- PostgreSQL 15 или новее;
- npm.

## Локальный запуск

1. Установите зависимости: `npm install`.
2. Создайте базу данных PostgreSQL и скопируйте `.env.example` в `.env`.
3. Настройте `DATABASE_URL`, `ARCHIVE_STORAGE_DIR` и `TOTP_ENCRYPTION_KEY`; при необходимости задайте `DB_POOL_SIZE`.
4. Примените схему: `npm run db:migrate`.
5. Создайте первого администратора, задав в окружении `BOOTSTRAP_ADMIN_USERNAME`, `BOOTSTRAP_ADMIN_PASSWORD` (не менее 12 символов) и `BOOTSTRAP_ADMIN_NAME`, затем выполните `npm run admin:create`.
6. Запустите сервер разработки: `npm run dev`.

Для PowerShell переменные окружения текущего сеанса задаются, например, так:

```powershell
$env:BOOTSTRAP_ADMIN_USERNAME = "admin"
$env:BOOTSTRAP_ADMIN_PASSWORD = "use-a-unique-long-password"
$env:BOOTSTRAP_ADMIN_NAME = "Администратор"
npm run admin:create
```

Не помещайте реальные пароли и строки подключения к БД в `.env.example`, исходный код или репозиторий.

Для TOTP задайте `TOTP_ENCRYPTION_KEY` как случайный ключ из 32 байт в шестнадцатеричном формате (64 символа). Сгенерировать его в PowerShell можно командой:

```powershell
[Convert]::ToHexString([Security.Cryptography.RandomNumberGenerator]::GetBytes(32))
```

Сохраните ключ в `.env` или защищённом хранилище секретов и не меняйте его после подключения пользователями TOTP: без него сохранённые секреты нельзя расшифровать.

## Импорт документов

Раздел «Импорт» доступен администраторам по адресу `/admin/import`. CSV и XLSX принимают таблицу с заголовками на русском или английском. Обязателен столбец `Название` (`title`); распознаются `Номер` (`number`), `Дата` (`date`), `Дата вступления в силу` (`effectiveDate`), `Дата завершения действия` (`expiryDate`), `Вид` (`type`), `Статус` (`status`), `Подразделение` (`department`), `Описание` (`description`), `Теги` (`tags`), `Тип файла` (`fileKind`) и `Файл` (`file`). Даты принимаются как `ДД.ММ.ГГГГ` или `ГГГГ-ММ-ДД`; теги в одной ячейке разделяются запятой или точкой с запятой.

ZIP может включать документы PDF, DOCX и XLSX. Если в архиве есть `manifest.csv` или `manifest.xlsx`, столбец «Файл» ссылается на путь документа внутри ZIP. Без manifest поддерживаемые файлы импортируются как отдельные документы по имени файла. После проверки система показывает возможные совпадения по номеру или названию и дате; для каждой записи можно создать документ, добавить файл к найденному совпадению либо пропустить запись.

Ограничения: до 1 000 строк в одном импорте, 100 МБ на файл, 10 МБ на manifest, 2 000 ZIP-записей и 1 ГБ суммарного распакованного объёма. Предпросмотр хранится до 24 часов; просроченные записи и файлы очищаются при следующем создании предпросмотра.

## Хранение и конфигурация

`ARCHIVE_STORAGE_DIR` обязателен для файловых операций. Укажите локальную папку с правами только у службы приложения и расположите её вне публичного каталога сайта. Приложение не публикует файлы напрямую: выдача идёт через проверяющий права API. `PUBLIC_BASE_URL` задаётся для ссылок редактирования Office и должен использовать HTTPS в production. `DB_POOL_SIZE` ограничивает размер пула PostgreSQL (по умолчанию 20).

Индикатор «Диск» показывает общую занятость файловой системы, на которой расположен `ARCHIVE_STORAGE_DIR`; подпись отдельно показывает фактический размер файлов в папке архива и доступное службе приложения место на этом диске. Символические ссылки при подсчёте размера архива не обходятся.

Production-запуск требует Node.js-службы/процесса и доступной PostgreSQL. Сборка использует Node adapter Astro. Пошаговое развёртывание версии проекта из GitHub на Ubuntu Server 24.04 для локальной сети, без домена и доступа из интернета, описано в [РАЗВЕРТЫВАНИЕ-LINUX.md](./РАЗВЕРТЫВАНИЕ-LINUX.md). Инструкция по production-запуску и автозапуску Windows в локальной сети — в [РАЗВЕРТЫВАНИЕ-WINDOWS.md](./РАЗВЕРТЫВАНИЕ-WINDOWS.md).

## Команды

| Команда | Назначение |
| --- | --- |
| `npm run dev` | Запуск локального сервера разработки |
| `npm run build` | Сборка SSR-приложения в `dist/` |
| `npm run preview` | Предварительный просмотр production-сборки |
| `npm test` | Тесты потоковой загрузки и CSV/XLSX/ZIP импорта |
| `npm run db:migrate` | Применение SQL-миграций |
| `npm run admin:create` | Однократное создание первого администратора |
| `npm run admin:password` | Установка нового пароля существующего администратора |

Для установки собственного пароля администратора задайте `ADMIN_USERNAME` и `ADMIN_PASSWORD` в PowerShell перед `npm run admin:password`. Пароль должен содержать от 12 до 1024 символов; не записывайте его в репозиторий и не отправляйте в чат.

В приложении реализованы каталог и карточки документов, роли администратора/редактора/читателя, локальные сессии с Argon2id, самостоятельная смена пароля текущего пользователя из меню профиля, управление справочниками и пользователями, журнал действий, загрузка/версии файлов и предпросмотр импорта. При смене пароля приложение проверяет действующий пароль и завершает остальные сессии пользователя, сохраняя текущую. Для production-релиза ещё необходимы интеграционные испытания на целевой PostgreSQL/Linux- или Windows-среде, проверка backup/restore и согласование антивирусной обработки файлов с инфраструктурой организации.
